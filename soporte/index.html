Antes de escribir

La documentación se lee entera de una sentada y cubre el editor, el formato .fluyo.json y el servidor MCP. Si tu duda es «¿cómo se hace X?», es muy probable que esté ahí.

Tiempo de respuesta

Fluyo es un proyecto de software libre gratuito, mantenido en tiempo libre y sin acuerdo de nivel de servicio. Dicho eso, el compromiso realista es este:

Tipo de asuntoPrimera respuesta
Privacidad, datos o asuntos legalesEn 72 horas
Vulnerabilidad de seguridadEn 72 horas
Todo lo demás — fallos, preguntas de uso, servidor MCP caídoEn una semana
Peticiones de mejora e ideasSin plazo. Se leen todas

«Primera respuesta» significa que alguien ha leído tu mensaje y te contesta, no que el problema esté resuelto. Un fallo reproducible suele arreglarse rápido; uno que no se puede reproducir puede quedarse abierto mucho tiempo.

Cómo escribir un buen reporte

Lo que más acelera un arreglo, por orden:

  • El archivo .fluyo.json con el que falla, si puedes compartirlo. Es lo único que permite reproducir el problema exactamente. Si el diagrama es confidencial, un ejemplo mínimo que falle igual sirve perfectamente.
  • Qué esperabas y qué pasó. «El GIF sale con un salto al reiniciar» dice mucho más que «la exportación no va bien».
  • Navegador y sistema operativo. Varias cosas del editor —el cuentagotas, el portapapeles, la pantalla completa— dependen de APIs que no están en todos los navegadores.
  • Errores de la consola, si sabes abrirla (F12).
  • Para el servidor MCP: qué cliente usas y si va por conector remoto o en local por stdio.

Seguridad

Si encuentras una vulnerabilidad, escribe al correo de arriba en privado y da un plazo razonable para corregirla antes de hacerla pública. La política completa está en SECURITY.md.

Contribuir

Los pull requests son bienvenidos y no requieren instalar nada: el editor es HTML, CSS y JavaScript sin dependencias ni paso de compilación. CONTRIBUTING.md explica la estructura y trae guías paso a paso para añadir un icono y una animación.

Para arreglos pequeños, manda el pull request directamente. Para cambios grandes, abre antes un issue: es más rápido acordar el enfoque que rehacer el trabajo.

Si necesitas más de lo que este proyecto puede dar

Si dependes de Fluyo para algo crítico y necesitas garantías de disponibilidad o tiempos de respuesta comprometidos, la respuesta honesta es que este servicio no puede dártelos. Lo que sí puedes hacer, sin pedir permiso a nadie:

  • Alojar tu propio editor. Son archivos estáticos: cualquier servidor sirve.
  • Desplegar tu propia instancia del servidor MCP, sin los límites del endpoint público.
  • Ejecutar el servidor MCP en local por stdio, sin red de por medio y sin ningún tope.

Todo está bajo licencia MIT y documentado en los repositorios. Es la ventaja concreta de que el proyecto sea libre.
